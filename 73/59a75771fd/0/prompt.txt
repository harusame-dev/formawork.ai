### 4. 原因の仮説（確度・高）
textarea L327 の `onClick={(event) =&gt; event.stopPropagation()}` が直接の原因です。

- 行のアクティブ化は **親 div の `onClick`（L303）への click イベントのバブリングに依存**している。
- textarea を直接クリックすると、L327 の `event.stopPropagation()` が click の伝播を止め、親 div の `onClick` に到達しない → `handleSelect` / `setSelectedId` が呼ばれず、その行がアクティブにならない。
- textarea 自体には `onFocus` や独自のアクティブ化処理がないため、フォーカスは当たる（カーソルは入る・入力もできる）のに、行の選択状態（`selectedId`）だけが更新されない、という「フォーカスとアクティブ化の不整合」が起きる。
- 一方、行の余白（番号セルや原文セル）をクリックした場合は伝播が止まらないため正常にアクティブ化される。これがバグ報告の「入力欄を直接クリックした時だけ選択されない」という症状と一致します。

補足: `stopPropagation` が置かれている意図は、おそらく結合モード（merge）時に textarea クリックで行が merge 選択トグルされるのを防ぐためと推測されます（normal モードでは textarea は `disabled`=false だが、merge/split モードでは L322 `disabled={!canEdit || mode !== "normal"}` で無効化されるため、実際には normal モード時のみ textarea が操作可能）。そのため、修正方針としては「textarea の `onFocus`（または `onClick`）で `handleSelect(segment.id)` を呼ぶ」ことで、伝播停止を維持したままアクティブ化を成立させられます（※今回は調査のみ、変更は行っていません）。</result>
