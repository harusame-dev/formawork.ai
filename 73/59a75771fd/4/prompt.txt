## 3. 確定すると何が起きるか（下書きとの機能的差分）

### (a) 翻訳メモリ(TM)への蓄積 — 最大の差分
確定時のみ `accumulateTranslationMemory`（`accumulate-translation-memory.ts:14-48`）が呼ばれ、原文を OpenAI 埋め込みベクトル化して `translation_memories` テーブルへ INSERT/UPDATE します（同一プロジェクト・同一原文があれば更新）。下書きや未訳の訳文は **TM に一切蓄積されません**。TM は他セグメント・他ワークの「類似の過去訳」として類似度検索で再利用されるため（`assist-panel.client.tsx:172-209`）、確定して初めて訳文が組織の資産になります。

なお埋め込み生成に失敗しても確定自体は成功扱いで、TM 蓄積失敗はログのみ（`confirm-segment.ts:38-39`, `accumulate-translation-memory.ts:44-47`）。

### (b) ワーク（ドキュメント）ステータスの再計算
確定・更新いずれもトランザクション内で `updateWorkStatus`（`update-work-status.ts:12-40`）を呼びます。判定基準は確定数ベースです。
```ts
if (total &gt; 0 &amp;&amp; confirmed === total) status = WorkStatus.Completed;   // 全確定で「完了」
else if (translated &gt; 0)              status = WorkStatus.InProgress;  // 訳出ありで「翻訳中」
// それ以外は NotStarted（未着手）
```
- `completed` は `status = Confirmed` のセグメント数で判定。**下書きは「完了」にカウントされない。**
- `translated`(=翻訳中) は `status &lt;&gt; Untranslated`（＝Draft または Confirmed）でカウント。下書きは「翻訳中」には寄与する。

WorkStatus 自体は `packages/db/src/schema/work.ts:15-26`（Completed:3 / InProgress:2 / NotStarted:1、ラベル 完了／翻訳中／未着手）。

### (c) UI 上の表示差分
- ステータスドット／バッジ（`segment-status-badge.universal.tsx:9-13`）: 未訳=グレー、**下書き=amber(琥珀)**、**確定=green**。エディタ行頭（`editor.client.tsx:306`）と AssistPanel ヘッダ（`assist-panel.client.tsx:98`）に表示。
- エディタ上部の進捗表示（`editor.client.tsx:58-64, 219`）は「確定 {confirmed}/{total}」で、**確定数のみ**を分子にカウント。下書きは進捗にカウントされない。

### (d) 確定後に再編集すると下書きへ戻る（不可逆ではない）
確定済みセグメントの textarea も編集可能（`editor.client.tsx:320-331`、disabled は `!canEdit || mode !== "normal"` のみ）。確定後に訳文を編集して blur すると `updateSegment` が走り、status は **Draft に降格**します（`update-segment.ts:23-26`）。つまり確定は最終ロックではなく、編集すれば下書きに戻る運用です。

### (e) 構造編集（結合・分割）時の扱い
- 結合 `merge-segments.ts:75`: 結合後の訳文があれば **Draft**、無ければ Untranslated。確定状態は維持されず Draft に落ちる。
- 分割 `split-segment.ts:42-46, 60-66`: 分割元は status・訳文を維持（確定なら確定のまま）、新規後半セグメントは Untranslated で挿入。
