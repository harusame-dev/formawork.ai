4 DB スキーマ設計

既存 packages/db/src/schema/ 規約に準拠：pgSchema(schemaName).table(...)、PK は uuid().primaryKey().defaultRandom()、enum は smallint + const、FK は .references(..., { onDelete: "cascade" })、全テーブル .enableRLS()（ポリシーは作らずアプリ層で認可）。

可視性とアクセス制御

projects.visibility が Public ならログインユーザー全員が閲覧可、Private は project_members に存在するユーザーのみ。判定は各ユースケースの認可ヘルパーで行う（RLS なし）。

共通用語集の表現

glossaries.project_id を nullable にし、NULL = 全プロジェクト共通。英訳時はプロジェクト用語集 + 共通用語集をマージして参照する。

pgvector の導入（既存の拡張導入パターンを踏襲）

Drizzle の generate は拡張を出力しないため、drizzle/00XX_enable_pgvector.sql を手書き追加し meta/_journal.json にエントリ追記（既存 0001_enable_pgmq.sql / 0002_enable_pg_cron.sql と同形式）。

embedding カラムは drizzle-orm/pg-core の customType で vector(1536) を自前定義（OpenAI text-embedding-3-small = 1536 次元）。

5 テキスト抽出・文分割

抽出：ライブラリ（AIではない）

  • docx：mammoth で段落テキストを抽出（書式は捨て、段落の区切りは保持）

6 AI 英訳 & RAG（翻訳メモリ・用語集）

1セグメントの英訳要求ごとに、類似過去訳と用語集を取得して Claude に渡す。

sequenceDiagram participant E as 対訳エディタ participant A as translateSegment.action participant U as ユースケース participant O as OpenAI(embedding) participant DB as pgvector / glossary participant C as Claude API E->>A: 英訳要求(segmentId) A->>A: 認証・認可・バリデーション A->>U: translateSegment(segment) U->>O: 原文を埋め込み O-->>U: vector(1536) U->>DB: 類似TM 上位5（cosine） + 用語集マッチ 上位5 DB-->>U: 過去訳・用語ペア U->>C: プロンプト（原文＋類似訳＋用語集） C-->>U: 英訳（単一） U-->>E: 訳文候補を表示（編集可）

類似 TM 検索

原文（和文）を OpenAI で埋め込み、translation_memories.source_embedding と cosine 距離で上位5件。プロジェクト単位でフィルタ。

用語集マッチ

原文に含まれる source_term を抽出（部分一致／trigram）。プロジェクト用語集 + 共通用語集から上位5件を訳語ヒントとして同梱。

TM への蓄積： セグメントを確定したタイミングで原文＋訳文を translation_memories へ insert し、原文の埋め込みも併せて保存。これが次回以降の類似検索の母集団になる。

方針メモ（AIの抽象化）： ご指定どおり Claude は SDK を直接利用し抽象化層を設けない。一方で OpenAI 埋め込みと docx 抽出は将来差し替えに備え薄いラッパーを推奨（外部ライブラリ規約）。この非対称は意図的なものとして明記する。

層の責務（既存規約）

ファイル 責務
*.action.ts 薄い Server Action。createServerAction でラップし schema(valibot)・role・onSuccess(updateTag/redirect) を指定。ロジックは持たない
*.ts（サフィックス無し） ユースケース本体・クエリ。DB アクセス、英訳、TM 検索、CSV 生成。Result を返す
*.server.tsx async な Container。データ取得して Presenter に渡す（末端で取得 + Suspense）
*.universal.tsx Presenter / Skeleton。props のみで描画
*.client.tsx 対訳エディタ等インタラクション。react-hook-form + valibotResolver
tag.ts / schema.ts キャッシュタグ定義 / valibot スキーマ

キャッシュは "use cache" + cacheTag（permanent）、更新側 Action で updateTag()。フォームは valibot（zod は使わない）、@repo/logger でセキュリティイベントを記録。

10 未決事項・リスク・確認したい点

論点 現時点の想定（提案） 確認したいこと
埋め込み対象 類似検索は原文（和文）で行う。確定訳の原文を埋め込み保存 英訳側でも検索したいニーズはあるか
TM 類似度の扱い 上位5件をスコア付きで提示（閾値での足切りはしない） 一定スコア未満を隠す等の要望有無
アップロード元ファイル保存 抽出後はファイルを保持せずテキスト（セグメント）のみ保存 原本を Supabase Storage に残す必要があるか
用語集の自動適用 英訳プロンプトにヒントとして渡すのみ（強制置換はしない） 確定訳での用語強制チェックまで要るか
同時編集 デモでは排他制御なし（後勝ち） 複数翻訳者の同時編集を想定するか
CSV フォーマット 原文, 訳文 の2列（UTF-8 BOM 付き） 列追加（用語/ステータス等）の希望
Docker 完結 後続。まずクラウド Supabase で動作 納品時点で Docker 起動が必須か

上記が固まれば M1（基盤・DBスキーマ）から着手します。特に「ファイル原本の保存有無」と「Docker 完結の必須度」はスキーマ・構成に影響するため、先に確認できると安全です。
