# Next.js アーキテクチャ レビュー報告

調査対象: `apps/web`（特にコミット `db4fcce` でのCATツール移行）。参照ガイドラインと突き合わせて確認できた事実のみを記載します。なお全体として `use cache` + `cacheTag` + `updateTag` によるキャッシュ無効化や、Container/Presenter 分離、末端Suspense（`WorksContainer`）など、ガイドラインに沿った良い実装が大半です。Critical/High 相当の致命的欠陥は見つかりませんでした。

## 良好な点（前提）
- データフェッチ関数（`get-*.ts`）に `"use cache"` + `cacheLife("permanent")` + `cacheTag(...)` が一貫して付与され、各ミューテーション `*.action.ts` の `onSuccess` で対応タグを `updateTag` 無効化している（`features/*/tag.ts` で集約）。

## 問題点リスト

### 1. クライアント起点の「データ取得」を Server Action で実装している
- **該当**: `apps/web/features/segment/assist-panel.client.tsx:57`（`useEffect` 内で `getSegmentAssistAction`）、`apps/web/features/segment/get-segment-assist.action.ts:12`、実体 `apps/web/features/segment/get-segment-assist.ts:17`
- **内容**: `getSegmentAssist` は DB 参照＋pgvector 類似検索＋用語集マッチを行う純粋な**読み取り**（ミューテーションなし）。これをセグメント選択ごとに Server Action として client から呼び出している。`translate-segment.action.ts` も同様にクライアントからの生成呼び出し（こちらは Claude 生成のためボーダーライン）。
- **なぜ問題か**: `agent-docs/nextjs-アーキテクチャガイドライン.md` の Route Handler 節「データフェッチなどのミューテーションを伴わないサーバー操作に使用すること」「クライアントからのデータフェッチ用 API には Route Handler を使用すること」に反する。実害として Server Action は React のキューで直列化され、GETキャッシュも効かないため、セグメントを素早く切り替えると assist 取得リクエストが直列で詰まる。

# セキュリティ・認証認可・DB設計レビュー報告

調査範囲: `apps/web/features` 配下の Server Action / Server Component、`apps/web/proxy.ts`、`apps/web/app/api`、`packages/db`・`packages/logger`・`packages/supabase`。コミット `db4fcce`（CAT 移行）で追加・変更された箇所を中心に、認可チェックは呼び出し元まで追跡して確認済み。

## 総評（堅牢に作られている点）

実コードを読んで確認した結果、認可の土台は健全です。誤検知を避けるため明記します。

- `createServerAction`（`apps/web/libs/create-server-action.ts:182-227`）が認証（`getUserStaffId`）・ロール（`role` オプション）・バリデーション（valibot `safeParse`）を一元実施。各 Action のロジック関数も `getProjectAccess` / `loadSegmentForEdit` / `canEditGlossary` を呼んでプロジェクトメンバーシップを再確認しており、確認した限りプロジェクト系・セグメント系・ワーク系・用語集系すべてに認可チェックがある。
- 認証は `supabase.auth.getUser()`（Auth サーバ検証あり）を `proxy.ts:46` と `supabase-auth.ts` の `getAuthUser()` 双方で使用。role/staffId は **`app_metadata`**（サーバ側のみ設定可）から取得しており、`user_metadata` 経由のなりすましは不可。妥当。
- pgvector 検索（`search-tm.ts`）の `vectorLiteral` は Drizzle `sql` テンプレートのバインドパラメータとして渡り、かつ埋め込みはサーバ生成の数値配列。**SQL インジェクションは成立しない**。
- ログのパスワード混入は、`packages/logger/src/sanitizer.ts:59-70` のキー名ベース redaction（`/^.*password.*$/` 等）で `{ input: { password } }` が再帰的に `[REDACTED]` 化されるため**実質的に防がれている**（login/change-password とも安全）。
- スタッフ管理（ユーザー作成・削除・編集）は `role: [UserRole.Admin]` でガード済み。

## High

### H-1. クライアントに露出するデフォルト管理者認証情報 + 同一パスワードでの admin シード
- 該当: `apps/web/.env.sample`（`NEXT_PUBLIC_DEFAULT_PASSWORD="Admin@789!"` / `NEXT_PUBLIC_DEFAULT_USERNAME=admin@example.com`）、`packages/supabase/src/fixtures/users-fixture.ts`（`adminUser` … `password: "Admin@789!", role: "admin"`）、シード実行 `packages/supabase/src/seed.ts:28-34`（`app_metadata: { role: "admin" }` で作成）
- 内容: `NEXT_PUBLIC_` プレフィックスのため管理者の既定資格情報がクライアントバンドルに出力される。同じ `Admin@789!` を持つ `role=admin` ユーザーがシードで作成される。
- 攻撃シナリオ: このシード/環境がデモ以外（本番・検証）に流用された場合、誰でも `admin@example.com` / `Admin@789!` で管理者ログイン → スタッフ作成・削除等の Admin 操作を奪取できる。
- 改善案: 本番ビルドでは `NEXT_PUBLIC_DEFAULT_*` を出力しない（デモ環境変数で分岐）。シードの admin パスワードは環境変数化し、本番シードから admin 固定資格情報を除外。
- 深刻度 High / 確信度 高（ただしログイン画面は「デモ環境です」と明記されており、デモ用途なら設計どおり。本番転用時のみ High）。

## Medium

### M-1. CSV エクスポートの数式インジェクション（Formula/CSV Injection）
- 該当: `apps/web/app/api/works/[workId]/export/route.ts`（`escapeCsv` … `"` のダブルクオート化のみ）、`apps/web/app/api/translation-memory/export/route.ts`（`escapeCsvField` 同様）
- 内容: 値を `"..."` で囲み `"` を二重化するのみで、先頭 `=`, `+`, `-`, `@`, タブ/CR を無害化していない。
- 攻撃シナリオ: 原文（アップロード docx 由来）や訳文（手入力）に `=HYPERLINK(...)` や `=cmd|...` 等を仕込み、確定 → TM 蓄積。出力 CSV を Excel/Sheets で開いた閲覧者の環境で数式・DDE が実行され、情報窃取につながる。`sourceText`/`targetText` は攻撃者が制御可能。
- 改善案: フィールドが `= + - @ \t \r` で始まる場合に先頭へ `'` を付与（または CSV ライブラリ使用）。
- 深刻度 Medium / 確信度 高。

- 該当: `apps/web/features/translation-memory/list/get-translation-memories.ts`（`"use cache"` + `cacheLife("permanent")` + `cacheTag(TranslationMemoryTag.All)`、引数 `userId` でキー化）。無効化側 `apps/web/features/project/members/remove-member.action.ts` は `ProjectTag.MembersByProjectId` / `ProjectTag.List` のみ `updateTag`。

- 改善案: `removeMember`（および `addMember`）で `TranslationMemoryTag.All` も無効化、または TM 一覧キャッシュをユーザー権限変更に追従させる。
- 深刻度 Medium / 確信度 中（グローバル無効化が頻繁に起きるため窓は限定的だが、認可のステイルは実在）。

### M-3. 機密原文の OpenAI 送信とドキュメント記載の不一致
